# 0.0.1 发布验证

当前发布使用 `Novel-Writer-master` 名称，从 `0.0.1` 开始新版本序列。旧 1.x 客户端需手动安装一次；不强制自动降级。初始发布工作流为 `.github/workflows/initial-brand-release.yml`。

## 本地验证

- better-sqlite3 固定为 12.11.1；[上游说明](https://github.com/WiseLibs/better-sqlite3/releases/tag/v12.11.1)明确修复 Electron 42 Windows 编译问题。锁文件仅更新该依赖，保留其他依赖版本。
- Node ABI 137 与 Electron 42.11.18 的 SQLite 加载均通过。
- TypeScript、渲染进程、主进程及 preload 构建通过。
- 品牌、发布资产合同、更新后端与更新状态定向测试 88 项通过；截图与文档检查另有 8 项通过（部分重叠）。
- 真正 Electron 的关于页、中英文浅色/深色界面及 4:3 宣传图素材场景通过。六组界面场景均无被记录的外部请求、真实配置目录写入或残留进程；模型请求使用本地夹具。
- 新导出 26 张真实界面素材，并据此生成中英文宣传主图。截图源、尺寸和 SHA-256 见 `docs/readme-visuals/captures-v0.0.1.json`。
- Windows 安装包、blockmap、latest.yml 已重新生成；打包后 SQLite/LanceDB 模块加载、安装文件哈希、更新清单和内嵌仓库地址检查通过。
- Windows 脚本编码已恢复 UTF-8 BOM，安装器脚本的 72 项测试通过、2 项条件跳过。
- 扩展发布脚本测试中，两项 Windows 监控合成进程链测试在本机持续超时（32 项中 29 项通过、1 项条件跳过）。未声称完整测试套件全部通过；独立的新版本工作流还会验证真实安装、运行与卸载。

旧版本迁移专用的 v0.2.5/v1.1.0 资产未被当作本次初始版本的验收材料。本次云端验证针对全新安装；旧项目与设置仍使用兼容的稳定目录和 appId。

## 发布暴露面审计

### 1. 总览

使用 reverse-engineering-exposure-audit 扫描当前 `dist` 和 Windows 解包目录。前端产物未检出扫描器列举的暴露项；这只是静态扫描结果。项目为 GPL-3.0 开源软件，不以隐藏客户端源码作为安全边界。

### 2. 发现清单

| 项目 | 静态证据 | 判断 |
| --- | --- | --- |
| PE-PDB | Electron 附带 D3D/Chromium 二进制的 PDB 引用，9 项 | 依赖自身的编译信息，不是本项目源码映射 |
| CLR-ASM | d3dcompiler_47.dll 中的 BSJB 字节序列 | 无法仅凭标记确认其为应用的 .NET 程序集，不作为已确认漏洞 |
| PE-SIGN | 7 个附带二进制未检出 Authenticode 签名目录 | 安装包未签名，已在发布说明披露 |
| ELECTRON-UNPACKED | 原生数据库与 Arrow 等模块位于 ASAR 外 | 原生模块正常加载需要，保留 |

### 3. 证据与处理

扫描覆盖 `dist/` 与 `release/0.0.1/win-unpacked/`；扫描原始记录位于本地 `.runtime/rebrand-v0.0.1/exposure-*.json`。未发现本项目发布产物中的明文长期凭证或源码 map。保持原生依赖正常加载，不删除必要文件或改写第三方已构建二进制。Electron fuse 状态和服务端接口权限不是本次静态结果的证明范围。

### 4. 客户端无法解决的问题

软件不提供付费授权服务或自带模型账号。用户自己的模型凭证由系统密钥库保存；客户端仍需在调用模型时使用它们，本次名称重置不改变这一架构。不能用混淆或打包方式代替账户与系统安全边界。

### 5. 后续顺序

先保证发布资产和更新清单哈希一致、平台包实际运行通过；证书签名需后续配置发布者证书，当前按既有允许未签名并披露的政策发布。没有将此次静态扫描描述为绝对安全证明。
