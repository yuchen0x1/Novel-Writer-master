# 2.0.0

## 📢 版本概述

本次更新修复项目设置保存、稿件导入与定稿发布、云备份、自动更新、提示词编辑和 MCP 连接等问题，并加固 PDF 导出隔离、模型凭据保存及发布工作流来源校验。Windows x64、macOS Apple Silicon 和 macOS Intel 共用同一个正式 Release。

## ✨ 新增功能

- 无。

## 🔧 改进与优化

- 关闭硬件加速的偏好现在从经过验证的全局配置读取，并在 Electron 启动渲染器前生效。
- 定稿、WebDAV 下载与云备份结果处理改为保留已提交结果，避免并发文件变更、短写或切换作品造成静默覆盖或误报失败。
- PDF 导出使用独立会话，不允许稿件 HTML 加载额外本地或远程资源。

## 🐛 问题修复

- 修复项目配置部分保存时清空未提交设置、单文件导入遗漏章节前言、归档稿干扰写作统计与检索等问题。
- 修复提示词编辑期间切换模板或较晚载入数据导致作者输入丢失；同一路径重开作品时不再复用旧会话的草稿读取。
- 修复模型连接测试被拒绝的请求卡住，以及更新检查并发、失败后重试、更新提示状态覆盖和自动检查节流问题。
- MCP 工具明确返回执行错误；断线、标准输入 EPIPE 和拆分的 UTF-8 消息能够及时、正确处理。
- Windows 安全文件 helper 处理标准输入错误及跨数据块中文响应；模型设置保存时保留其他模型无法解密的密文 API Key。
- Python IDaaS 请求签名继续遵守服务端协议；标记 MD5 仅用于非安全协议兼容，不用于凭据保护。

## 🔒 安全与兼容性

- 初始发布工作流只允许从默认分支的当前提交构建，并禁用跨运行依赖缓存。
- `2.0.0` 高于旧 `1.x` 和中间 `0.0.x` 系列，正式安装版可以通过现有更新源收到提示；作品数据目录和 appId 保持不变。
- Windows 安装包未做 Authenticode 签名；macOS 安装包为 ad-hoc 签名，未进行 Developer ID 签名或公证。
- 作品和设置目录继续沿用。更新前建议先导出作品归档；不要为降级覆盖新版本创建的作品数据。

## Release overview

This release fixes project settings, manuscript import and finalization, cloud backup, update checks, prompt editing, and MCP transport. It also strengthens PDF export isolation, model credential preservation, and the source boundary of the initial release workflow. Windows x64, macOS Apple Silicon, and macOS Intel share one official Release.

## Improvements

- The hardware acceleration preference is read from verified global configuration and applied before Electron creates the renderer.
- PDF export uses an isolated session that cannot load additional local or remote resources.

## Fixes

- Fixed partial project settings updates clearing omitted values, single-file manuscript import dropping preface text, and archived drafts affecting writing statistics and search.
- Prompt edits are preserved while switching templates or when data loads later. Reopening a project at the same path no longer reuses a stale draft read.
- Fixed rejected model connection tests remaining stuck, and update-check concurrency, retries, state initialization races, and automatic-check throttling.
- MCP tool errors are reported as failures. Disconnects, stdin EPIPE, and UTF-8 messages split across chunks are handled correctly.
- Windows safe-file helpers now handle stdin failures and split UTF-8 responses. Saving a model preserves another model's encrypted API key when it cannot be decrypted.
- The IDaaS request signature remains compatible with its server protocol; MD5 is explicitly marked as non-security protocol compatibility and is not used to protect credentials.

## Security and compatibility

- The initial release workflow builds only the default branch's current commit and does not share dependency caches across runs.
- Version `2.0.0` bridges the previous `1.x` and interim `0.0.x` sequences, so official installed clients can detect this update through the existing source.
- The Windows installer is not Authenticode-signed. macOS builds are ad-hoc signed and are not notarized.
- Existing book and settings directories are retained. Export a book archive before updating; do not overwrite data created by a newer version when downgrading.

## Upgrade and data migration

- Compatibility: upgrades from official `1.x` and `0.0.x` releases are supported because `2.0.0` is higher than both version sequences.
- Configuration and data: books, model settings, and writing language remain in the existing data directory.
- Rollback: there is no automatic binary rollback. Export a book archive first and use the supported project-copy import flow when rolling back.

## Verification

- Platform installer qualification, official Release readback, and Windows in-app update results are evidenced by their GitHub Actions runs.

- Non-official portable builds or installations with a modified update source are outside the automatic-update guarantee.
